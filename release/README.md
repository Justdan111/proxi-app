# Release documents

Prepared on day 4. Everything here is a draft for review — none of it has been published,
submitted, or filled into a console.

| Document | What it is for |
|---|---|
| [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md) | The order to do things in, and what blocks what. **Start here.** |
| [DEVICE_QA.md](DEVICE_QA.md) | The physical-device test pass. Never run — days 1–3 are all unverified |
| [PRIVACY_POLICY.md](PRIVACY_POLICY.md) | Publishable policy text. Needs a public URL |
| [DATA_DISCLOSURES.md](DATA_DISCLOSURES.md) | Exact answers for the App Store labels and Play Data Safety form |
| [STORE_LISTING.md](STORE_LISTING.md) | Listing copy, keywords, categories, screenshot plan |

Every `<TO FILL — ...>` marks something that could not be decided from the repo: a contact
address, a support URL, a legal judgement, or a decision that is yours.

The privacy and disclosure documents were written against the source, not against intent.
If what the app sends changes, re-check them — an inaccurate disclosure is a rejection
reason on its own, and a worse one than a vague policy.
